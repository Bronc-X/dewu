# 得物生图前端设计需求书

版本：v1.0  
面向对象：前端设计团队、前端开发团队  
范围：仅定义前端产品体验、信息架构、页面结构、组件、交互、状态、动效和交付物要求；不定义后端算法实现。

## 1. 产品定位

本产品是面向电商图片生产的工具型产品，不是营销展示页，也不是单次换背景小工具。前端需要呈现一个可批量工作、可追踪进度、可复核质量、可沉淀项目资产的智能图片生产工作台。

核心体验目标：

- 让买家和卖家都能围绕一个“项目”完成图片生产、复核、下载和返修。
- 以项目分类承载四个核心功能，避免把所有能力堆在一个上传页里。
- 页面优先服务效率、可读性和批量处理，不做夸张品牌宣传和过度装饰。
- 视觉上复刻 iOS 26 Liquid Glass / Glass Liquid 的透明、折射、柔光和层叠质感，但必须保持工具产品的清晰、克制和可用性。

## 2. 目标用户

### 2.1 卖家用户

卖家用户关注批量上新、成本控制、商品一致性和交付效率。

典型任务：

- 上传棚拍图或白底图，批量生成可上架商品图。
- 按商品、款式、活动或店铺项目管理图片。
- 快速判断哪些图可用、哪些需要返修。
- 下载单张图、批量 zip、质检报告和可交付素材。

### 2.2 买家用户

买家用户关注商品真实感、穿搭效果、可信度和购买决策。

典型任务：

- 浏览商品在不同场景中的上身效果。
- 对比不同背景、姿态、光照下的真实观感。
- 反馈图片是否可信、是否有明显合成痕迹、是否影响购买判断。

前端主工作台优先服务卖家生产流程，同时在预览和复核模块中保留买家视角的真实感检查。

## 3. 项目分类与四个核心功能

首页和侧边栏必须以“项目”为一级组织方式。项目不是文件夹装饰，而是承载任务、素材、结果、复核和下载的工作单位。

### 3.1 项目分类

至少支持四类项目入口：

| 项目类型 | 适用对象 | 设计重点 |
|---|---|---|
| 商品上新项目 | 卖家 | 批量上传、批量生成、批量下载 |
| 款式复用项目 | 卖家 | 同一商品多背景、多场景复用 |
| 活动投放项目 | 卖家 | 统一视觉风格、统一交付规格 |
| 买家预览项目 | 买家/运营 | 场景真实感、效果对比、反馈收集 |

### 3.2 四个核心功能

每个项目内都应围绕以下四个核心功能组织界面：

1. 素材导入  
   上传原图、查看素材清单、识别图片质量、标记无效输入。

2. 智能生成  
   启动批量处理，展示主体识别、抠图、背景匹配、合成、光影修复和质检进度。

3. 结果复核  
   查看原图、抠图、中间图、最终图、状态、问题原因和修复建议，支持按状态筛选。

4. 交付导出  
   下载单图、批量 zip、质检报告、项目结果包，并展示导出历史。

## 4. 信息架构

### 4.1 全局导航

建议结构：

- 项目
- 素材库
- 背景库
- 生成历史
- 质检报告
- 设置

全局导航应保持短、稳定、可扫描。不要使用营销式导航，如“探索能力”“开启未来”等。

### 4.2 项目详情页

项目详情页是核心工作区，必须包含：

- 项目名称、项目类型、当前状态、创建时间、素材数量、生成进度。
- 四个功能区入口：素材导入、智能生成、结果复核、交付导出。
- 当前批次列表和最近一次生成结果。
- 异常提醒，如上传不足、格式错误、生成失败、质检未通过。

### 4.3 结果详情页

单张结果详情页必须展示：

- 原图
- 抠图或透明主体图
- 使用的背景
- 最终图
- 状态：通过、可参考、未通过、处理中、失败
- 质量原因
- 修复建议
- 背景编号、处理耗时、生成批次、下载入口

## 5. 布局要求

产品主布局采用两段式或三段式，不使用落地页式大 hero。

### 5.1 两段式布局

适用于列表、历史、素材库、背景库。

- 左侧：固定宽度导航或项目分类。
- 右侧：主内容区。

适合页面：

- 项目列表
- 素材库
- 背景库
- 生成历史
- 设置

### 5.2 三段式布局

适用于高频生产工作台。

- 左侧：项目分类、批次列表、筛选器。
- 中间：核心画布、上传区、结果网格或对比视图。
- 右侧：参数、状态、质检详情、操作面板。

适合页面：

- 项目详情页
- 批量生成页
- 结果复核页
- 单图详情页

### 5.3 响应式

- 桌面端优先，建议最小设计宽度 1280px。
- 1024px 以下收起右侧面板，改为抽屉或底部面板。
- 移动端以查看、复核、下载为主，不承担完整批量生产流程。
- 所有按钮、标签、文件名、状态文字必须避免溢出和遮挡。

## 6. 视觉风格

### 6.1 Liquid Glass / Glass Liquid 方向

需要复刻 iOS 26 Liquid Glass / Glass Liquid 的视觉语言，但不要牺牲信息密度。

可使用：

- 半透明玻璃面板
- 背景模糊和轻微折射感
- 柔和边缘高光
- 分层悬浮工具栏
- 轻量阴影
- 细描边
- 背后内容透出但不影响阅读

必须控制：

- 不使用大面积炫光、彩色光斑、装饰性渐变球。
- 不让玻璃透明度影响表格、状态、报告文本可读性。
- 工具区背景要足够稳，关键文字对比度必须达标。
- 卡片圆角建议 8px 以内；玻璃容器可略大，但不得显得松散。

### 6.2 色彩

建议使用中性色为主，少量品牌蓝/青/荧光绿用于状态和操作提示。

状态色建议：

| 状态 | 色彩方向 |
|---|---|
| 通过 | 绿色 |
| 可参考 | 琥珀色 |
| 未通过 | 红色 |
| 处理中 | 蓝色 |
| 等待中 | 灰色 |

避免整页只有一种蓝紫、奶油、棕橙或深蓝色调。图片生产工具要有清爽、冷静、可靠的工作感。

### 6.3 字体与密度

- 中文界面优先使用系统字体。
- 标题清晰但不夸张，工作台内不使用 hero 级大标题。
- 表格、列表、状态、原因说明要保持高可读性。
- 数字、进度、耗时、批次编号要对齐，方便扫描。

## 7. 技术要求

### 7.1 前端技术栈

前端实现建议：

- React
- Tailwind CSS
- Motion 动效库必须使用，优先使用 `motion/react` 或项目实际选定的 Motion 封装。

### 7.2 组件原则

- 优先使用可复用的工作台组件，不做一次性页面拼贴。
- 使用 Tailwind 表达布局、间距、颜色、透明度和响应式。
- 复杂状态组件要有清晰 props 和状态命名。
- 不新增无必要的 UI 框架依赖，除非项目已有规范要求。

## 8. 页面需求

### 8.1 项目首页

目标：让用户快速进入最近项目、创建项目、查看处理状态。

必须包含：

- 项目分类入口。
- 最近项目列表。
- 新建项目按钮。
- 项目状态摘要：待处理、处理中、待复核、已完成、异常。
- 最近生成批次。

交互：

- 点击项目进入项目详情。
- 点击分类筛选项目。
- 新建项目弹窗需选择项目类型、项目名称、目标用途。

状态：

- 空状态：引导创建第一个项目。
- 加载中：使用 skeleton，不使用全屏空白。
- 异常：明确显示无法加载项目的原因和重试入口。

### 8.2 项目详情页

目标：围绕一个项目完成素材、生成、复核、导出。

必须包含：

- 项目摘要栏。
- 四个核心功能 tab 或 stepper。
- 当前批次进度。
- 最近结果网格。
- 右侧操作面板。

交互：

- 切换功能区时保持项目上下文。
- 生成中允许用户查看已完成单张结果。
- 有失败项时可按失败原因筛选。

### 8.3 素材导入页

目标：支持批量上传和输入质量检查。

必须包含：

- 拖拽上传区。
- 文件列表。
- 单图缩略图。
- 格式、尺寸、数量、重复文件检查。
- 上传成功、失败、等待上传状态。

交互：

- 支持拖拽排序。
- 支持删除单张。
- 支持继续补充上传。
- 未满足批量要求时禁用开始生成，并说明原因。

### 8.4 智能生成页

目标：让用户理解系统正在做什么，而不是只看到一个转圈。

必须包含：

- 总进度。
- 单图处理队列。
- 当前步骤：主体识别、抠图、背景匹配、合成、光影修复、质检、导出。
- 预计耗时或已耗时。
- 可展开的处理日志摘要。

交互：

- 生成中禁止重复提交。
- 支持暂停或取消时，必须清楚说明取消后的结果保留规则。
- 已完成图片可提前预览。

### 8.5 结果复核页

目标：让运营或卖家快速判断可用性。

必须包含：

- 结果网格。
- 状态筛选。
- 对比视图。
- 质量原因和修复建议。
- 单图下载。
- 批量选择和批量下载。

对比视图至少支持：

- 原图 / 最终图并排。
- 原图 / 抠图 / 背景 / 最终图四列。
- 点击查看大图。

### 8.6 交付导出页

目标：明确交付内容，减少找文件成本。

必须包含：

- 单图下载。
- 批量 zip 下载。
- report.html / report.json 下载。
- 项目导出历史。
- 导出状态和失败原因。

交互：

- 下载动作要有可见反馈。
- 导出失败时提供重试。
- zip 未生成时展示生成中或重新生成入口。

### 8.7 背景库页

目标：管理和预览背景资源。

必须包含：

- 背景缩略图网格。
- 背景编号。
- 类型、适配姿态、色温、光照方向、风险备注。
- 搜索和筛选。

交互：

- 点击背景查看详情。
- 在项目生成前可选择默认背景策略，但不要强迫普通用户手动选背景。

## 9. 关键组件

### 9.1 ProjectCard

展示项目名称、类型、状态、最近批次、完成数量、异常数量和更新时间。

### 9.2 GlassPanel

统一承载 Liquid Glass 面板效果。需要定义透明度、背景模糊、边框、高光、暗色模式适配。

### 9.3 UploadDropzone

支持拖拽、点击上传、格式提示、错误提示、上传进度和禁用态。

### 9.4 BatchProgress

展示批次总进度和单图状态。必须能表达排队、处理中、成功、可参考、失败。

### 9.5 ResultCard

展示最终图、状态、背景编号、耗时、下载按钮、查看详情入口。

### 9.6 QualityBadge

统一展示通过、可参考、未通过、处理中、失败等状态。

### 9.7 CompareViewer

支持并排、四列、大图查看、缩放和适配容器。

### 9.8 RightInspector

右侧检查器，用于展示参数、状态、质量原因、修复建议、导出操作。

## 10. 交互状态

所有用户路径必须覆盖以下状态：

- loading：数据加载、上传中、生成中、导出中。
- loaded：正常展示内容。
- empty：无项目、无素材、无结果、无导出历史。
- error：网络失败、上传失败、生成失败、导出失败。
- disabled：条件未满足时按钮禁用，并说明原因。
- partial success：批量任务部分成功、部分失败。
- reviewing：结果待人工复核。

错误文案必须具体，避免只显示“失败”。示例：

- “还有 3 张图片未上传完成，暂不能开始生成。”
- “第 5 张图片尺寸过小，建议替换为更高清原图。”
- “zip 生成失败，可重试导出；已生成的单图不会丢失。”

## 11. Motion 动效要求

必须使用 Motion 动效，不接受只有 CSS transition 的实现。

### 11.1 必须动效

- 页面进入和功能区切换：轻量 fade + y 位移。
- 左侧项目或批次切换：选中态滑动高亮。
- 上传文件进入列表：缩放 + 淡入。
- 队列进度更新：进度条平滑变化。
- 结果卡片生成完成：轻量 reveal。
- 右侧检查器打开/关闭：滑入滑出。
- 大图预览：共享元素或接近共享元素的放大过渡。

### 11.2 动效原则

- 动效服务状态变化，不做炫技。
- 单次动效建议 120ms-280ms。
- 生成进度可以使用循环动效，但必须低干扰。
- 支持 reduced motion，用户系统开启减少动态效果时应降级为淡入淡出或无动效。

## 12. 可访问性与可用性

- 所有按钮必须有 hover、active、focus、disabled 状态。
- 图标按钮必须有 tooltip 或 aria-label。
- 关键状态不只依赖颜色，还要有文字标签。
- 上传、生成、下载等关键动作要防重复提交。
- 大图预览支持键盘关闭。
- 结果列表支持键盘 tab 到主要操作。
- 图片缩略图需有合理 alt 文本。

## 13. 前端交付物

设计团队需交付：

- 页面流程图。
- 信息架构图。
- 桌面端核心页面高保真稿。
- 1024px 和移动端关键响应式稿。
- 组件清单和状态规范。
- Motion 动效说明，包括触发条件、时长、缓动、降级方案。
- Liquid Glass 视觉规范，包括背景模糊、透明度、描边、阴影和暗色模式策略。
- 图标、状态色、间距、字体、圆角规范。
- 空状态、错误状态、加载状态、部分成功状态示例。

前端开发需交付：

- React 页面和组件实现。
- Tailwind 样式实现。
- Motion 动效实现。
- 关键交互的本地可运行预览。
- 主要页面的响应式检查。
- 上传、生成、复核、导出的状态闭环。

## 14. 验收标准

- 用户可以从项目首页创建项目并进入项目详情。
- 用户可以在项目内完成素材导入、智能生成、结果复核、交付导出四个核心流程。
- 项目分类清晰，买家预览和卖家生产场景不混淆。
- 两段式和三段式布局在对应页面成立，桌面端信息密度足够。
- Liquid Glass 风格可见，但不影响文字、表格、缩略图和状态阅读。
- Motion 动效覆盖关键状态变化，并支持 reduced motion。
- 所有核心路径都有 loading、empty、error、disabled、partial success 状态。
- 页面不是营销文案，不使用落地页式 hero，不出现夸张宣传语。
- 文档、设计稿和组件说明足够让前端团队直接拆任务实现。
