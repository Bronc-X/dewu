# AI 商品图商业合作方案：对内决策版

> 内部使用版本。基于对外版 BP、当前项目实现、PhotoRoom 替代路线、自研模型/训练研究、投入预算测算整理。  
> 本文不用于直接发给合作方，重点服务内部判断：做不做、先做哪一段、投多少钱、什么时候止损或加码。

## 1. 内部结论

这个项目不应被定义为“从零训练一个 PhotoRoom”。更合理的定位是：

> 先用可插拔第三方能力完成商业验证，再用自研工作流沉淀数据，逐步替换为自有抠图、合成、质检和局部编辑模型。

核心判断：

1. 第一阶段的价值不在模型训练，而在建立商品图生产闭环：项目、素材、批次、复核、导出、失败原因、返修记录。
2. 训练的首要对象不是生图大模型，而是抠图、商品保护、质检分类、失败原因判断和风格/背景选择。
3. AI 背景生成和重光照是成本最高、稳定性最难的部分，应放在第二阶段以后。
4. 商业上早期不要开放 3 元/张价格，除非有明确月度保底和高自动化能力。
5. 技术上不能承诺“不会被平台识别为 AI”，只能承诺“可追踪、可复核、尽量符合平台规则”。

建议内部采用三段式路线：

| 阶段 | 路线 | 时间 | 资金 | 目标 |
|---|---:|---:|---:|---|
| P0 验证 | PhotoRoom/外部工具 + 本地交付闭环 | 2 到 4 周 | 5 到 20 万元 | 验证商家需求、平台审核、交付标准 |
| P1 MVP | 自研抠图/合成/质检闭环，外部 API 可插拔 | 8 到 12 周 | 40 到 100 万元 | 建立可积累数据的产品系统 |
| P2 Beta | 自研模型微调、批量并发、人工复核平台 | 4 到 6 个月 | 120 到 300 万元 | 支撑代运营规模化订单 |

如果 P1 阶段无法证明 5 元/张有稳定毛利、平台审核可接受、返修率可控，则不建议进入 P2。

## 2. 当前项目基础

当前项目不是空白状态，已经具备一个适合继续演进的底座：

1. 后端采用 FastAPI/Jinja，本地可运行。
2. 已有项目、批次、复核、导出方向的产品结构。
3. 已经预留 provider 架构：
   - `MATTING_PROVIDER`：抠图来源。
   - `COMPOSITING_PROVIDER`：合成来源。
   - `BACKGROUND_PROVIDER`：背景生成来源。
4. 已接入或预留真实工具：
   - PhotoRoom Remove Background。
   - PhotoRoom Image Editing。
   - Adobe Firefly。
   - Adobe Photoshop API。
   - OpenAI-compatible 图像/视觉模型。
5. 当前原则是未配置真实 key 时明确报错，不伪造成功结果。

内部判断：这个架构适合继续走“第三方 provider -> 自研 provider -> 自研模型”的替换路径，不需要推倒重来。

## 3. 对外版与对内版的关键差异

| 项目 | 对外版口径 | 对内真实判断 |
|---|---|---|
| 技术表达 | 自研工作流 + 第三方增强 + 后续微调 | 短期高度依赖 PhotoRoom/外部 API，自研先做闭环和质检 |
| 模型训练 | 后续基于数据微调 | 第一阶段不训练生图大模型，只训练/校准抠图和质检 |
| 成本表达 | 算力、API、研发、运维 | 最大不确定成本是标注、返修和人工质检，不是 S3 |
| 平台合规 | 平台合规可用 | 需要真实上架/发布测试，不能靠口头判断 |
| 定价 | 8/5/3 元分层 | 早期只建议 8 元和 5 元，3 元必须绑定保底 |
| 竞争策略 | 不绑定单一供应商 | 供应商短期不可完全替代，必须避免过早自研全链路 |

## 4. PhotoRoom 功能拆解与自研替代

PhotoRoom 不是一个单点模型，而是一套产品化能力。自研替代也必须拆模块。

| PhotoRoom 功能 | 自研对应模块 | 优劣判断 |
|---|---|---|
| Remove Background | SAM 2 + BiRefNet + MODNet | PhotoRoom 更稳；自研可控但要标注数据 |
| AI Backgrounds | Qwen-Image-Edit / SDXL + ControlNet | 自研可做得物风格，但主体一致性风险高 |
| Background Image Replacement | mask + 规则合成 + 背景库 | 自研最容易先替代，稳定性可控 |
| AI Shadows | 接触点检测 + 阴影规则 + 局部修复 | PhotoRoom 明显更成熟，自研难度高 |
| Relighting | 色彩迁移 + 局部重光照 + 编辑模型 | 自研能定制冷灰电商风，但需要大量质检 |
| Batch Workflow | 队列、对象存储、数据库、Worker | 自研可完全掌控，也是项目长期壁垒 |
| 质量检查 | Qwen3-VL + DINOv2 + 规则 | 自研最有机会超过 PhotoRoom，因为可按得物规则判断 |
| 人工编辑 | Canvas mask 编辑 + 局部重跑 | 是产品化关键，但不一定需要大模型 |

内部优先级：

1. 先替代固定背景合成和质检。
2. 再替代抠图。
3. 最后替代 AI 背景和重光照。

## 5. 模型模块评分标准

以下评分是“免训练成熟度分”，不是模型强弱分。

定义：

- 100 分：几乎不用训练，只做工程接入、规则和阈值。
- 50 分：可用，但要较多 workflow、LoRA、人工筛选或阈值校准。
- 0 分：基本要从头做模型、数据、训练和工程。

评分维度：

| 维度 | 权重 | 解释 |
|---|---:|---|
| 功能原生匹配度 | 20 | 这个模型天生是不是就做这件事 |
| 开箱可用质量 | 20 | 不微调时，在得物商品图上能不能跑 |
| 领域数据依赖 | 20 | 是否依赖大量得物图、mask、偏好数据 |
| 商品保护可控性 | 15 | 是否容易改鞋型、Logo、衣服版型、脸和姿势 |
| 工程成熟度 | 15 | 批量、速度、部署、社区工具链是否成熟 |
| 商用/许可证清晰度 | 10 | 许可证越清晰，分数越高 |

更新评分：

| 模型/模块 | 对应能力 | 免训练分 | 内部判断 |
|---|---|---:|---|
| 规则模块 | 定位、缩放、留白、blur、基础合成 | 96 | 几乎纯工程，不需要训练 |
| DINOv2 | 商品不变性检测 | 84 | 可直接做图图相似度，但要调业务阈值 |
| SigLIP/OpenCLIP | 背景匹配、风格筛选 | 79 | 开箱可用，细粒度 Logo/鞋面不足 |
| SAM 2 | 主体/区域分割 | 74 | 粗 mask 和交互式选区好用，商业抠图还要修 |
| Qwen3-VL | 质检、中文失败原因 | 68 | prompt 可先跑，稳定判断要人工标签校准 |
| BiRefNet | 抠图/前景背景分离 | 63 | 起步好，但白鞋、头发、椅子边缘要微调 |
| MODNet | 人像头发 alpha | 56 | 人像强，商品/道具/坐姿场景泛化一般 |
| SDXL + ControlNet + IP-Adapter | 可控背景生成 | 50 | 生态成熟，但主体一致性和商品保护要流程控制 |
| Qwen-Image-Edit | AI 背景、局部编辑、扩图、重光照 | 48 | 贴近需求，但要训练成得物风格并防止改商品 |
| 阴影/重光照模块 | AI Shadows / relighting | 32 | 没有现成模型稳定包圆，需规则 + 生成 + 质检闭环 |
| 端到端 PhotoRoom 式大模型 | 全流程一体化 | 12 | 平台级研发，不建议第一阶段做 |

内部含义：

- 70 分以上模块可以第一阶段直接接入。
- 50 到 70 分模块可以做小规模微调或人工校准。
- 50 分以下模块不要作为 MVP 核心承诺。

## 6. 推荐技术路线

### 6.1 P0：交付验证期

目标：不证明自研模型，只证明商业需求和交付标准。

做法：

1. 使用 PhotoRoom Web App 或 API 完成批量抠图、AI 背景、下载。
2. 本地系统负责编号、归档、质检、返修记录、交付包。
3. 每张图都记录：
   - 原图。
   - 结果图。
   - 使用工具。
   - 提示词。
   - 是否通过。
   - 失败原因。
   - 返修次数。

成功标准：

| 指标 | P0 要求 |
|---|---:|
| 测试图量 | 50 到 200 张 |
| 通过/可参考比例 | 不低于 60% |
| 失败原因可归类比例 | 不低于 90% |
| 平台审核样本 | 至少覆盖主图、详情图、种草图 |
| 商家付费意愿 | 至少 20 到 50 家试点商家有明确反馈 |

### 6.2 P1：自研 MVP

目标：让系统不只是调用外部工具，而是开始沉淀自研能力。

优先开发：

1. `self_hosted_matte`：SAM 2 + BiRefNet 抠图。
2. `self_hosted_composite`：规则落位、固定背景库、阴影、色温匹配。
3. `self_hosted_qc`：DINOv2 商品保护分数 + Qwen3-VL 中文质检。
4. 人工复核台：通过、可参考、失败、失败原因、返修建议。
5. 数据集导出：训练集、验证集、失败集、优质样例集。

不建议在 P1 做：

1. 全量训练 Qwen-Image-Edit。
2. 从零训练端到端商品图模型。
3. 承诺完全替代 PhotoRoom。
4. 承诺平台不会识别 AI。

P1 验收：

| 指标 | 要求 |
|---|---:|
| 月处理能力 | 1000 到 3000 组 |
| 单组 6 张交付 | 可追踪、可返修、可导出 |
| 质检一致性 | 与人工判断一致率 75% 以上 |
| 商品保护 | 明显改鞋型/Logo/衣服的图不能进入 pass |
| 单张可变成本 | 可稳定测算 |
| 5 元/张毛利 | 有正向空间 |

### 6.3 P2：Beta 商用版

目标：开始减少外部 API 依赖，提升自动化和毛利。

开发重点：

1. BiRefNet / matting 微调。
2. Qwen3-VL 质检微调。
3. Qwen-Image-Edit LoRA，用于得物冷灰外景、坐姿支撑、干净电商背景。
4. 阴影和重光照闭环。
5. 对象存储、任务队列、GPU Worker、权限与日志。
6. 商家、SKU、项目、批次、交付包、账单统计。

P2 验收：

| 指标 | 要求 |
|---|---:|
| 月处理能力 | 3000 到 10000 组 |
| 自动 pass 比例 | 60% 以上 |
| 人工返修比例 | 持续下降 |
| 平台审核 | 主图/详情图/种草图分场景有记录 |
| 3 元/张开放条件 | 月度保底 1.5 万组以上 |

## 7. 数据与标注计划

数据是这个项目的核心资产。没有数据闭环，不建议投入大训练。

### 7.1 必要数据

| 数据 | 字段/标注 | 用途 |
|---|---|---|
| 原始商品上身图 | SKU、类目、姿势、光照、拍摄背景 | 输入分布 |
| 人/商品/服装/鞋/椅子 mask | 多区域 mask、alpha matte | 抠图和商品保护 |
| 背景库 | 场景、地面、光照、色温、站姿/坐姿适配 | 背景匹配 |
| 合成结果 | pass/review/fail | 质检模型 |
| 失败原因 | 绿边、漂浮、商品变形、光照不合、坐姿错误 | 自动诊断 |
| 人工修图前后对比 | 原图、人工成品、返修记录 | 学习目标 |
| 平台审核结果 | 通过、退回、原因、场景 | 合规策略 |

### 7.2 数据量建议

| 阶段 | 数据量 | 说明 |
|---|---:|---|
| P0 | 50 到 200 张真实图 | 验证流程和平台反馈 |
| P1 | 1000 到 3000 张原图，300 到 800 张精标 mask | 微调抠图和质检 |
| P2 | 1 万到 5 万张原图，5000+ 高质量 mask，5 万到 20 万条质检/偏好标签 | 做垂直可商用替代 |

标注优先级：

1. 鞋、衣服、Logo、图案、脸、手、头发、椅子。
2. 白鞋、白衣、绿幕、棚拍、坐姿、透明道具。
3. 失败原因和返修动作。

## 8. 云服务与基础设施

内部需要的服务不是只有 GPU。

| 模块 | 供应商/服务 | 用途 |
|---|---|---|
| 对象存储 | S3 / OSS / COS / Azure Blob | 原图、mask、中间图、结果图、训练集、模型文件 |
| GPU 算力 | AWS EC2 GPU / SageMaker / 阿里 PAI / RunPod / Lambda Labs / CoreWeave | 训练、微调、批量推理 |
| 训练平台 | SageMaker Training / Vertex AI / Azure ML / 自建 PyTorch + Docker | 跑训练任务和实验复现 |
| 标注平台 | SageMaker Ground Truth / CVAT / Label Studio / 标注外包 | mask、质检、偏好排序 |
| 中转站 | API Gateway + Redis/SQS/RabbitMQ + Worker | 上传、排队、分发 GPU、回写结果 |
| 数据库 | Postgres / RDS / DynamoDB | 项目、商家、批次、标签、账单 |
| 推理服务 | SageMaker Endpoint / Triton / FastAPI GPU Worker | 在线生成和批量处理 |
| 监控安全 | IAM、KMS、Secrets Manager、CloudWatch | 权限、密钥、日志、成本追踪 |

内部建议：

1. P0/P1 不要重度上 SageMaker 全家桶，可以先用对象存储 + 自建 Worker。
2. 训练和大批量推理再短租 GPU，不要长期保留 H100。
3. 如果客户数据敏感，先用国内 OSS/COS + 本地或国内 GPU，避免跨境合规问题。

## 9. 投入时间和成本

### 9.1 重新核验后的阶段预算

| 路线 | 时间 | 资金 | 适合目标 |
|---|---:|---:|---|
| A. 不训练，只接现成模型 | 3 到 5 周 | 10 到 30 万元 | demo 和流程验证 |
| B. 核心自研 MVP | 8 到 12 周 | 40 到 100 万元 | 自研抠图、合成、质检闭环 |
| C. Beta 商用版 | 4 到 6 个月 | 120 到 300 万元 | 标注、LoRA、批量处理、人工审核 |
| D. 得物垂直可商用替代 | 6 到 12 个月 | 300 到 800 万元 | 专门针对得物商品图稳定产出 |
| E. 泛化 PhotoRoom 竞品 | 12 到 24 个月 | 1000 万元以上 | 多行业、多风格、平台级能力 |

内部推荐先批 40 到 60 万元，做 B 路线的低配版，先验证：

1. 5 元/张是否能形成正毛利。
2. 平台审核是否可接受。
3. 人工返修比例是否可被流程压低。
4. 数据是否足够支撑下一阶段训练。

### 9.2 P1 预算拆分

| 成本项 | 预算区间 | 备注 |
|---|---:|---|
| 算法/ML 工程 | 8 到 20 万元 | 抠图、质检、模型评估 |
| 后端/平台工程 | 8 到 18 万元 | provider、队列、存储、项目/批次 |
| 前端/复核台 | 5 到 12 万元 | 上传、复核、状态、导出 |
| 标注与人工质检 | 5 到 20 万元 | mask、失败原因、偏好数据 |
| GPU/API/存储 | 3 到 10 万元 | 外部 API、短租 GPU、对象存储 |
| 试点运营和返修 | 5 到 15 万元 | 商家沟通、返修、验收 |
| 预留风险 | 5 到 10 万元 | 平台审核、供应商额度、返工 |

### 9.3 成本敏感点

1. 单张成本不能只算推理费，还要算失败重试、人工复核、返修、下载整理和客服沟通。
2. 备选图会放大成本。按源图收费时必须限制备选数量。
3. 3 元/张只有在高自动化和高保底下成立。
4. 训练成本最大的不确定性不是 GPU，而是高质量标注和失败样本积累。

## 10. 商业模型内部判断

对外版中的价格逻辑基本成立，但内部要加上闸门。

| 价格 | 内部判断 | 开放条件 |
|---:|---|---|
| 8 元/张 | 适合试点、高级外景、种草图 | 可早期开，但要强调效果和人工复核 |
| 5 元/张 | 第一阶段主价格 | 平台审核可接受，返修率可控 |
| 3 元/张 | 不适合早期开 | 月度保底 1.5 万组以上，自动化足够高 |

建议商务策略：

1. 试点期不要做低价规模盘。
2. 先用 8 元和 5 元验证商家价值。
3. 对代运营方采用“技术底价 + 代运营加价”，避免固定比例分成。
4. 3 元价格必须绑定保底量和交付边界：默认 1 张最终图，额外备选和复杂返修另计。

## 11. 风险清单

| 风险 | 影响 | 内部处理 |
|---|---|---|
| 平台不允许主图使用 AI 背景 | 商业模型受限 | 分主图、详情图、种草图分别验证 |
| AI 改商品或 Logo | 高风险，可能误导消费者 | DINOv2/视觉质检 + 人工复核拦截 |
| PhotoRoom/API 成本不可控 | 毛利被吃掉 | provider 级成本记录，逐步替换高频环节 |
| 抠图边缘不稳 | 返修率高 | 先标注白鞋、头发、绿幕、坐姿高风险样本 |
| 阴影/重光照不自然 | 结果像假图 | 不作为 P1 核心承诺，优先固定背景合成 |
| 代运营方商家量不足 | 达不到保本规模 | 试点前确认商家数、月均组数、保底量 |
| 数据授权不清 | 后续训练有法律风险 | 只用自有/授权商品图，留存来源和授权记录 |
| 供应商许可变化 | 商用受限 | 优先 Apache/MIT 模型；非商用模型只做内部实验 |

## 12. 决策闸门

### P0 到 P1 闸门

满足以下条件再投入 P1：

1. 至少 50 到 200 张真实图完成处理和质检。
2. 合格/可参考比例不低于 60%。
3. 平台审核测试没有出现不可接受的硬性禁止。
4. 至少 20 家试点商家或等价商家池有真实意向。
5. 失败原因能稳定归类。

### P1 到 P2 闸门

满足以下条件再进入模型微调和规模化投入：

1. 月处理 1000 到 3000 组不崩。
2. 5 元/张有正毛利空间。
3. 自动质检与人工判断一致率达到 75% 以上。
4. 返修率有下降趋势。
5. 已积累 1000 到 3000 张原图和 300 到 800 张高质量 mask。

### 3 元价格开放闸门

必须同时满足：

1. 月度保底 1.5 万组以上。
2. 默认只交付 1 张最终图。
3. 自动 pass 比例 70% 以上。
4. 复杂外景、额外备选、人工返修另计费。
5. 边际成本稳定低于 0.7 元/张或有明确下降路径。

## 13. 内部行动清单

短期 2 周：

1. 用 50 到 200 张真实图完成平台和效果测试。
2. 建立 `pass/review/fail` 质检表。
3. 记录每张图的失败原因、返修动作和耗时。
4. 确认得物、小红书等使用场景和 AI 标识规则。
5. 与代运营方确认商家池、月均组数、现有人工成本。

中期 8 到 12 周：

1. 增加 `self_hosted` provider。
2. 接入 SAM 2 / BiRefNet 抠图评估。
3. 接入 DINOv2 商品保护分数。
4. 接入 Qwen3-VL 质检和中文失败原因。
5. 建立训练数据导出格式。
6. 形成 P1 成本仪表盘。

进入 P2 前：

1. 做 Qwen-Image-Edit LoRA 小样。
2. 做 BiRefNet/matting 微调。
3. 做质检模型微调。
4. 建立标注供应链和质量抽检机制。
5. 签订数据授权、保密和商业使用边界。

## 14. 内部一句话判断

这个项目值得做，但第一阶段不值得押注“自研大模型”。正确打法是：

> 用外部工具验证商业闭环，用自研系统沉淀数据和质检标准，用分阶段 provider 替换逐步降低成本，最后只在最有业务价值的模块上训练模型。

第一笔预算建议控制在 40 到 60 万元；如果 P1 的交付质量、平台合规和 5 元/张毛利没有跑通，不进入百万级模型训练阶段。
